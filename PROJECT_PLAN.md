# PROJECT_PLAN — Esports Hub

## Архитектура
- `server.js` — Express: `/api` + статика (`index.html`, `assets/`).
- `src/parser/bo3.js` — адаптер BO3.GG: robots.txt, извлечение `window.__NUXT__` в изолированном vm, маппинг сущностей.
- `src/services/sync.js` — цикл синхронизации, блокировка от параллельных запусков, журнал `sync_runs` / `sync_errors`.
- `src/database/` — SQLite, миграции по порядку из `migrations/*.sql`, upsert по `(game_code, source_id)`.
- `src/scheduler/` — node-cron, расписание `SYNC_CRON`.
- `src/routes/api.js` — REST API. Frontend (`assets/js/*.js`, ES-модули без сборки) берёт данные только из него, маршрутизация через History API.
- `src/routes/admin-api.js`, `src/auth/` — админ-API, сессии, хеширование паролей. `src/content/markdown.js` — безопасный рендер статей. `src/seo.js` — мета-теги, robots.txt, sitemap.

## Модели
games, teams, players, tournaments, matches, match_teams, articles, sync_runs, sync_errors.

## Этап 1 — сделано
Матчи (сейчас / предстоящие / завершённые) по трём дисциплинам, команды с логотипами, турниры, анонсы статей,
базовые карточки игроков, страница матча с картами, поиск, статус синхронизации, адаптивная вёрстка.

## Ограничения этапа 1
- Игроки попадают в базу только из тегов новостей — составов мало.
- Подробная статистика матча не загружается: пути `*/matches/*/*/*` запрещены robots.txt.
- Детальные страницы команд/турниров BO3.GG пока не обходятся.

## Следующие этапы
1. Очередь обхода `/teams/{slug}`, `/players/{slug}`, `/tournaments/{slug}` с лимитом запросов за цикл.
2. Составы и статистика игроков, таблицы турниров.
3. Полные статьи — только с разрешения BO3.GG.
4. PostgreSQL и кеш API при росте нагрузки.
5. Запрос официального доступа к данным BO3.GG.

## Ограничения этапа 3
- Рейтинг Valve — только CS2; для Dota 2 и LoL есть лишь текущее место команды BO3.GG, история — из собственных снимков.
- Статистика профилей BO3.GG — за 6 месяцев; другие периоды недоступны (`?period=` запрещён robots.txt).
- Ссылки «предыдущий матч» в сетке BO3.GG часто пустые — сетка строится по раундам и позициям.
- Статистика игроков на турнире публикуется в основном для CS2.

## Этап 4 (выполнено)
- Новый дизайн и навигация по настоящим адресам, главная из `/api/home`, быстрый поиск с подсказками, страница настроек.
- Собственные статьи и гайды: миграция 004, публичный каталог, страница статьи с оглавлением, редактор в админ-панели.
- Серверная авторизация администратора (scrypt, HttpOnly-сессии, CSRF, ограничение попыток), загрузка обложек.
- Общий поиск по пяти разделам с фильтрами; фильтры матчей по периоду, tier и названию.
- Быстрая проверка live-матчей (`LIVE_SYNC_CRON`), индикатор актуальности, кэш API с ETag, периодический опрос в браузере.
- SEO: серверные мета-теги, 404, SSR текста статей, robots.txt, sitemap.xml, noindex админки; CSP и защитные заголовки; сжатие ответов.

## Ограничения этапа 4
- Обновления — периодический опрос, не трансляция: счёт live-матча отстаёт от BO3.GG на интервал `LIVE_SYNC_CRON` + интервал опроса браузера.
- Админ-панель работает только когда сайт и API на одном домене (Node.js отдаёт оба).
- Один уровень вложенности списков в Markdown; встраивание видео не поддерживается.
- Поиск — по вхождению подстроки (LIKE), без морфологии; при большом объёме стоит перейти на FTS5 или PostgreSQL.
- Загруженные обложки хранятся на диске сервера (`uploads/`) — их нужно включать в резервные копии вместе с `data/`.
